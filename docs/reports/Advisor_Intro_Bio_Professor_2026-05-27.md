# 지도교수님 상담용 Lattice 소개 문서

Date: 2026-05-27
Purpose: 바이오 전공 지도교수님께 프로젝트를 짧게 소개하고, 실무적인 조언을 받기 위한 비기술 설명 문서
Audience: 컴퓨터공학 배경이 없는 바이오/의생명과학 연구자
Status: 상담용 요약 문서. 제품/런타임 계약 문서가 아님.

## 0. 먼저 보여드릴 1페이지 요약

**프로젝트 이름:** Lattice
**대상 사용자:** 논문을 많이 읽고, 근거를 확인하며, 미팅/발표/후속 탐색으로 이어가야 하는 바이오 연구자
**핵심 문제:** 논문을 읽은 뒤 핵심 주장, 실제 근거, 한계, 미팅 자료가 흩어져서 같은 확인 작업을 반복하게 됨
**해결 방향:** 논문별로 주장, 근거, 불확실성, 후속 산출물을 연결해 저장하고 사람이 다시 검토하기 쉽게 보여주는 개인 연구 보조 도구

교수님께 드릴 가장 짧은 설명:

> "Lattice는 논문 PDF를 AI로 한 번 요약하고 끝내는 도구가 아니라, 논문에서 어떤 주장이 어떤 근거에 기대는지 남겨두고, 나중에 lab meeting이나 journal club 준비에 다시 쓸 수 있게 해주는 연구 보조 도구입니다."

상담 때 꼭 받고 싶은 조언:

- 실제 바이오 연구자가 논문을 검토할 때 가장 먼저 확인해야 하는 정보는 무엇인지
- AI가 만든 논문 요약에서 어떤 오류가 가장 위험한지
- lab meeting 준비용으로 어떤 형태의 결과물이 가장 쓸모 있는지
- 어떤 세부 분야 또는 논문 묶음으로 pilot test를 해보면 좋을지

## 1. 한 문장 소개

**Lattice는 논문 PDF를 단순히 요약하는 도구가 아니라, 논문에서 claim, 근거, 한계, 불확실성을 분리해 저장하고, 나중에 미팅 자료나 비교표 같은 연구 산출물로 다시 쓸 수 있게 해주는 개인 연구 보조 워크스페이스입니다.**

쉽게 말하면, 논문을 읽고 나서 매번 다시 찾아보게 되는 내용을 다음과 같이 남겨두는 시스템입니다.

- 이 논문의 핵심 주장은 무엇인지
- 그 주장이 논문 어디에 근거를 두는지
- 어떤 수치, 그림, 표, 실험 결과를 근거로 봐야 하는지
- 어떤 부분은 아직 불확실하거나 사람 검토가 필요한지
- lab meeting, journal club, 후속 논문 탐색에 어떻게 재사용할 수 있는지

## 2. 왜 만들고 있는가

바이오 연구에서 논문을 읽는 일은 단순한 요약으로 끝나지 않습니다. 실제로는 아래 작업이 반복됩니다.

- 논문 핵심 내용 파악
- 실험 디자인, cohort, assay, endpoint 확인
- figure/table에서 실제 근거 찾기
- claim과 evidence가 맞는지 검토
- 한계와 caveat 정리
- 관련 논문을 이어서 찾기
- 미팅용 자료나 다음 실험/분석 아이디어로 바꾸기

문제는 이 과정에서 **요약, 근거, 판단 이유, 발표 자료가 서로 흩어지기 쉽다**는 점입니다. AI 요약 도구를 써도 빠르게 초안은 만들 수 있지만, 나중에 "이 문장이 논문 어디에서 나온 말이지?", "이 주장은 얼마나 강하게 뒷받침되지?", "교수님께 설명할 때 caveat는 무엇이지?"를 다시 확인해야 합니다.

Lattice는 이 반복 비용을 줄이기 위해 만들고 있습니다. 목표는 AI가 논문을 대신 믿어달라는 것이 아니라, **논문을 읽은 결과를 근거가 보이는 상태로 정리해 사람이 더 빨리 검토하게 하는 것**입니다.

## 3. 현재 프로젝트가 잘하려는 일

현재 Lattice가 집중하는 흐름은 다음 하나입니다.

```text
논문 PDF
  -> 구조화된 논문 이해
  -> claim/evidence/uncertainty 검토
  -> 관련 논문 탐색 기준 정리
  -> 미팅용 초안 또는 비교 산출물 생성
```

현재 기준으로 보여드릴 수 있는 핵심 기능은 아래와 같습니다.

| 기능 | 교수님께 설명할 때의 의미 |
| --- | --- |
| Paper Notes | 논문별로 제목, 상태, 핵심 claim, 근거, 관련 정보를 모아 보는 화면 |
| Analysis Workbench | claim, evidence, uncertainty를 실제로 검토하는 작업 화면 |
| Evidence-linked state | 요약문만 저장하지 않고, 어떤 문장/표/그림 근거를 봐야 하는지 연결해두는 방식 |
| Research DNA | 관심 연구 질문에 맞춰 후속 논문을 어떻게 찾고 선별할지 남기는 검색/스크리닝 기준 |
| Meeting Pack | 저장된 논문 이해 상태를 바탕으로 lab meeting이나 journal club용 초안을 만드는 산출물 |
| Method/Chart/Image/Protocol artifacts | 여러 논문 비교, 차트용 정리, 이미지 근거, protocol 관련 정보를 따로 검토하는 확장 산출물 |

## 4. 무엇이 아닌가

교수님께 보여드릴 때 오해를 줄이기 위해 아래는 명확히 빼고 설명하는 것이 좋습니다.

- 범용 챗봇이 아닙니다.
- 논문 내용을 자동으로 "정답"으로 확정하는 시스템이 아닙니다.
- 실험실 전체의 ELN/LIMS를 대체하려는 도구가 아닙니다.
- 여러 사람이 동시에 쓰는 협업 플랫폼이 아직 아닙니다.
- 프로젝트 관리, 과제 관리, 실험 관리 시스템이 핵심 목표는 아닙니다.
- AI가 생성한 발표자료를 그대로 믿고 쓰자는 제품이 아닙니다.

현재 가장 정확한 설명은 **개인 연구자가 논문을 근거 중심으로 읽고, 그 결과를 재사용 가능한 연구 자산으로 남기는 도구**입니다.

## 5. 교수님께 보여드릴 데모 흐름

상담 시간에는 기술 설명보다 실제 연구 흐름으로 보여드리는 것이 좋습니다.

### 5.1 첫 화면: 논문 목록

보여드릴 것:
- 저장된 논문들이 논문 단위로 정리되어 있음
- 각 논문이 단순 파일이 아니라 검토 상태와 연결되어 있음

설명 문장:
> "논문 PDF를 넣으면 그냥 요약 파일을 만드는 것이 아니라, 논문별로 검토 상태와 근거 정보를 남기도록 만들고 있습니다."

### 5.2 논문 상세 화면

보여드릴 것:
- 논문 제목/메타데이터
- 핵심 claim
- 근거 위치 또는 근거 문장
- warning, uncertainty, review-needed 상태

설명 문장:
> "AI 요약에서 끝나는 게 아니라, 어떤 claim이 어떤 근거를 보고 나온 것인지 다시 확인할 수 있게 하는 것이 핵심입니다."

### 5.3 근거 검토 화면

보여드릴 것:
- claim과 evidence가 분리되어 있음
- 근거가 약하거나 위치가 불확실하면 확정처럼 보이지 않게 표시
- 사람이 검토해야 할 부분을 남김

설명 문장:
> "바이오 논문에서는 claim이 그럴듯한지보다, 실제 데이터가 그 claim을 얼마나 지지하는지가 중요해서 이 부분을 분리해 보여주려고 합니다."

### 5.4 Meeting Pack 또는 미팅용 초안

보여드릴 것:
- 논문 기반 one-page summary
- 발표 흐름
- 예상 질문
- caveat와 uncertainty

설명 문장:
> "저장된 논문 이해 상태를 lab meeting이나 journal club 준비물로 바꾸는 부분입니다. 다만 이 산출물은 최종 진실이 아니라, 근거를 다시 확인할 수 있는 초안입니다."

## 6. 교수님께 받고 싶은 조언

상담 목적은 "기술이 멋있는지"보다, 실제 연구자가 쓸 만한지 확인하는 것입니다. 아래 질문을 드리면 좋습니다.

### 6.1 문제 적합성

- 논문을 읽고 미팅 준비를 할 때, 실제로 가장 시간이 많이 드는 부분은 무엇인가요?
- claim, figure/table evidence, caveat를 따로 정리하는 방식이 실제 연구 흐름에 맞나요?
- 바이오 연구자 입장에서 "이 정도는 자동화되면 좋겠다"와 "이건 사람이 꼭 봐야 한다"의 경계는 어디인가요?

### 6.2 신뢰성과 검토 방식

- 논문 claim을 정리할 때 반드시 확인해야 하는 항목은 무엇인가요?
- figure, table, method, cohort, endpoint, statistical result 중 어떤 정보가 가장 먼저 보여야 하나요?
- AI가 만든 요약이나 미팅 초안에서 어떤 종류의 오류가 가장 위험한가요?
- "근거가 약함", "위치 불명확", "사람 검토 필요" 같은 표시가 실제로 도움이 될까요?

### 6.3 데모와 사용성

- 교수님이나 대학원생이 처음 봤을 때 가장 먼저 이해해야 하는 화면은 무엇이어야 하나요?
- lab meeting 준비용으로 본다면 어떤 출력물이 가장 유용할까요?
- journal club, systematic review 준비, grant background 정리 중 어느 use case가 가장 설득력 있어 보이나요?

### 6.4 발전 방향

- 특정 분야, 예를 들어 oncology, neuroscience, immunology, microbiome, clinical study 중 어디에 먼저 맞추는 것이 좋을까요?
- pilot test를 한다면 어떤 종류의 논문 5-10편으로 검증하는 것이 좋을까요?
- 교수님 기준에서 "이 정도면 연구실에서 써볼 만하다"고 판단할 최소 기준은 무엇인가요?

## 7. 교수님께 강조할 핵심 차별점

### 7.1 요약이 아니라 근거 검토 중심

많은 도구가 논문을 빠르게 요약합니다. Lattice의 초점은 요약 속도보다 **요약이 어떤 근거에 기대고 있는지 다시 확인할 수 있게 하는 것**입니다.

### 7.2 AI draft와 검토된 판단을 구분

AI가 만든 초안은 편리하지만, 연구 판단으로 바로 승격되면 위험합니다. Lattice는 draft, evidence-backed, review-needed 같은 상태를 구분해 사람이 검토할 수 있게 하려는 방향입니다.

### 7.3 논문 읽기 이후의 재사용

논문을 한 번 읽고 끝내는 것이 아니라, 나중에 아래 작업에 다시 쓰는 것을 목표로 합니다.

- journal club 발표
- PI 미팅 준비
- 관련 논문 screening
- method 비교
- figure/table evidence 확인
- 연구 배경 정리

## 8. 현재 한계

상담에서 솔직히 말할 부분도 분명히 두는 것이 좋습니다.

- 아직 완성된 상용 제품이 아니라 prototype입니다.
- 현재는 개인 연구자 중심입니다.
- 모든 바이오 세부 분야에 최적화되어 있지는 않습니다.
- AI가 뽑은 claim/evidence는 사람이 검토해야 합니다.
- PDF 품질, figure/table 추출 품질에 따라 결과가 달라질 수 있습니다.
- 교수님이나 실제 대학원생이 쓰는 workflow에 맞춰 우선순위를 더 좁혀야 합니다.

## 9. 5분 설명 스크립트

아래는 교수님께 그대로 말할 수 있는 버전입니다.

> 교수님, 제가 만들고 있는 Lattice는 바이오 논문을 단순히 요약하는 도구라기보다, 논문을 읽고 나서 남겨야 하는 claim, 근거, 한계, 불확실성을 구조적으로 정리해두는 개인 연구 보조 도구입니다.
>
> 논문을 읽다 보면 핵심 주장은 기억나도, 그 주장이 어느 figure나 table, 어느 문장에 근거했는지 나중에 다시 찾게 되는 경우가 많습니다. 또 lab meeting이나 journal club을 준비할 때 매번 요약, caveat, 예상 질문, 관련 논문 탐색 기준을 다시 정리하게 됩니다.
>
> Lattice는 PDF를 넣으면 논문 단위로 핵심 claim과 evidence를 분리해서 저장하고, 근거가 약하거나 위치가 불확실한 부분은 확정처럼 보이지 않게 표시하려고 합니다. 그리고 그 상태를 바탕으로 미팅용 초안이나 관련 논문 탐색 기준 같은 산출물로 이어지게 만드는 것이 목표입니다.
>
> 제가 교수님께 여쭤보고 싶은 건 기술적인 평가보다, 실제 바이오 연구자 입장에서 이 흐름이 맞는지입니다. 예를 들어 논문을 검토할 때 어떤 정보가 제일 먼저 보여야 하는지, AI 요약에서 어떤 오류가 가장 위험한지, lab meeting 준비용으로 어떤 출력물이 실제로 유용할지 조언을 받고 싶습니다.

## 10. 상담 당일 체크리스트

- 기술 용어는 최소화한다.
- "AI가 대신 판단한다"가 아니라 "사람이 검토하기 쉽게 정리한다"고 설명한다.
- 실제 논문 1편을 기준으로 보여준다.
- claim, evidence, uncertainty가 분리되어 보이는 장면을 꼭 보여준다.
- Meeting Pack은 최종 발표자료가 아니라 검토 가능한 초안이라고 말한다.
- 마지막에는 구체적인 조언 질문 3-5개를 남긴다.
